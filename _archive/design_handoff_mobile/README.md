# Handoff: restaurant-log 모바일 화면

## 개요
`taehyeon-k/restaurant-log` (Next.js App Router)의 기존 데스크톱 화면(지도 + 오른쪽 기록 창)을 폰에서 쓸 수 있게 만드는 작업입니다.
데스크톱 화면은 그대로 두고, 좁은 화면에서만 새 모바일 레이아웃(지도 + 바텀시트)을 보여줍니다.
모바일에는 데스크톱의 모든 기능이 들어가고, 두 가지가 추가됩니다: 카메라 방문인증 흐름, 인증 없는 직접 기록 쓰기.

## 이 폴더의 파일에 대해
`DINARY 모바일 v3.dc.html`, `DINARY 통합.dc.html`은 **HTML로 만든 디자인 참고물(시제품)**입니다. 그대로 가져다 쓰는 프로덕션 코드가 아닙니다.
할 일은 이 디자인을 **저장소의 기존 환경(Next.js + React + TypeScript + Tailwind/기존 스타일 규칙)에서 다시 구현**하는 것입니다. 데이터 접근은 기존 `src/lib/queries.ts`, 타입은 `src/lib/types.ts`, 가격 규칙은 `src/lib/price.ts`를 그대로 씁니다. 시제품 안의 하드코딩된 예시 데이터(SEED / NEARBY)는 버리고 실제 데이터로 대체합니다.

브라우저에서 두 HTML 파일을 열면 실제로 동작합니다 (`support.js`, `public/piggy.png` 필요). 동작을 확인한 뒤 구현하세요.

## 완성도
**하이파이(hifi)** 입니다. 색·타이포·간격·라운드·그림자·상호작용이 최종값입니다. 아래 값 그대로 재현하세요. 다만 저장소에 이미 정의된 색/토큰이 있으면 그것을 우선하세요 — 값은 동일합니다(`src/app/globals.css`의 종이 톤 팔레트와 같은 계열).

## 반응형 전환

- 분기점: `max-width: 820px` → 모바일, 초과 → 기존 데스크톱.
- 권장 구현: `src/app/page.tsx`에서 서버 컴포넌트로 데이터를 받고, 클라이언트 컴포넌트 하나(`MobileShell.tsx`)와 기존 `Workspace.tsx`를 CSS로 나눠 렌더 (`hidden lg:flex` / `flex lg:hidden`)합니다. JS `matchMedia`로 한쪽만 마운트해도 되지만, CSS 분기가 SSR과 궁합이 좋습니다. 지도 인스턴스가 두 개 생기지 않도록, 숨겨진 쪽은 렌더하지 마세요 (Leaflet은 `display:none` 안에서 크기 계산이 깨집니다) — `useMediaQuery`로 하나만 마운트하는 편이 안전합니다.
- 모바일 뷰포트: `viewport-fit=cover`, 높이는 `100dvh`.

### 6. 카메라 방문인증 흐름 (모바일 전용, 3단계)
**6-1 촬영** — 전체 배경 `#171614`. `<video autoplay playsinline muted>`를 `top:152px; left:16px; 340×352`, radius 28px, `object-fit:cover`. 위에 "지금 여기"(Gowun Batang 700 18px 흰색) + 상태 알약(배경 `rgba(251,250,246,.12)`, 11px). 하단 셔터 78×78(테두리 `3px solid rgba(251,250,246,.85)`, 안에 62px 흰 원), 왼쪽 카메라 전환 44×44, 오른쪽 갤러리 선택(`<input type="file" accept="image/*" capture="environment">`). 맨 아래 "갤러리에서 고른 사진은 인증되지 않아요".
- 권한 거부/미지원/4초 타임아웃이면 영상 영역을 대체 카드로 바꿔 메시지 + "사진 찍어 올리기"(파일 입력) + "다시 시도" 제공. 메시지 문구는 시제품의 `camMessage()` 그대로 쓰세요.
- 촬영은 `<canvas>`로 프레임을 잡아 최대 900px로 줄여 `image/jpeg` 0.72로 인코딩. 전면 카메라면 좌우 반전.

## 상호작용 · 동작

- 시트: 핸들 드래그(pointer 이벤트, `touch-action:none`)로 높이를 직접 바꾸고, 놓으면 가장 가까운 스냅으로. 핸들 탭은 peek → half → full 순환. 스냅이 바뀌면 280ms 후 `map.invalidateSize()`.
- 지도 검색: 엔터 또는 "찾기". 이름·지역·주소·종류에 부분 일치. 결과가 한 가게면 `flyTo(좌표, 15, {duration:.7})` 후 그 가게 화면을 열고, 여러 곳이면 목록 검색어로 옮겨 담고 `fitBounds`(`paddingTopLeft:[36,120]`, `paddingBottomRight:[36,40]`, `maxZoom:15`).
- 목록 검색: 가게 이름·지역·종류·주소 + 각 방문의 메뉴·메모까지 부분 일치.
- 핀: 데스크톱과 같은 물방울 모양(24px, `border-radius:50% 50% 50% 0`, `rotate(-45deg)`), 종류별 색. 재방문이면 색으로 채우고 흰 테두리, 아니면 흰 배경 + 색 테두리. 선택된 핀은 30px + 테두리 2px + 코어 10px. 탭하면 가게/기록 화면. 모바일에서는 상시 툴팁을 달지 않습니다(가림).
- 지도 자동 맞춤: 필터 결과가 바뀔 때만 `fitBounds`. 수정 중이거나 인증 흐름 중에는 지도를 건드리지 않습니다.
- 전환: 시트 높이·FAB 위치 `.26s cubic-bezier(.32,.72,0,1)`. 그 외 화면은 즉시 교체(오버레이).
- 스크롤바는 숨김(`::-webkit-scrollbar { width:0 }`).
- 탭 대상은 모두 44px 이상.
