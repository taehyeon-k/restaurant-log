## A. 지도 화면 플로팅 버튼

파일: `app/(tabs)/index.tsx` (플로팅 컨트롤 위치 계산부)

1. 시트 위 왼쪽의 마커 필터 칩(「둘 다 / 기록만 / 위시리스트만」)을 **삭제**한다. 마커 표시 여부는 시트의 세그먼트(맛집 기록 ↔ 위시리스트) 선택만 따른다.
2. 내 위치 버튼(44×44 원)을 **+ 버튼 왼쪽, 같은 높이**로 옮긴다.
   - + 버튼: `right: 84`, 52×52
   - 내 위치: `right: 148`, 세로 중심을 + 버튼에 맞춤 (`top = plusTop + 4`)
   - 시트 높이가 바뀔 때 + 버튼과 같은 애니메이션(0.26s)으로 따라 움직인다.
3. 보관함 버튼은 지금 위치(오른쪽 끝) 그대로.

## B. 위시 추가 (+ → 「계획 추가」)

+ 메뉴의 두 번째 항목을 누르면 전체 화면 폼 「가고 싶은 곳」이 뜬다. 레이아웃은 **기록 쓰기 폼과 같은 양식**(라벨은 Mono 10px 대문자 간격, 입력칸 높이 46~48, radius 14~16, 테두리 `#ded8cb`)을 쓴다.

위에서부터:

1. 헤더: 「가고 싶은 곳」(Gowun 18) · 오른쪽 「취소」
2. **링크** 버튼 (점선 `#c9a593` 1.5px, 높이 56): 링크 아이콘 + 「링크」 + 오른쪽 Mono 「릴스 · 쇼츠」
   - 누르면 클립보드의 URL을 읽어 「어느 가게인가요」 화면으로 이동 (B-2)
   - 링크가 붙으면 버튼 자리에 출처 줄로 바뀜: 검정 재생 아이콘 + 「쇼츠에서 담음 · youtube.com/shorts/…」 + ✕
3. **사진** 버튼 (같은 스타일): 사진 아이콘 + 「사진」 + Mono 「앨범」
   - 앨범에서 캡처 1장을 고른다. 붙으면 썸네일(44×58) + 「캡처 1장 · 나만 보여요」 + ✕
   - 캡처는 본인만 볼 수 있다. 공유·커뮤니티에 절대 노출하지 않는다.
4. **가게**: 텍스트 입력, placeholder 「가게 이름」
5. **위치**: 텍스트 입력, placeholder 「주소나 동네」
   - 가게 이름을 검색해서 후보를 고르면 위치에 주소가 자동으로 들어간다 (기록 쓰기와 같은 동작, 카카오 로컬 검색 재사용)
   - 위치 옆 「지도에서 고르기」 버튼은 두지 않는다
6. **종류**: 칩 10개 — 한식 중식 일식 양식 아시안 분식 커피 디저트 베이커리 차 (단일 선택, 다시 누르면 해제)
7. **어떤 장소인가요?**: 메모 textarea (Gowun 14, 높이 150), placeholder 「어디서 봤는지, 왜 가보고 싶은지 적어 두면 좋아요」 (「마음껏 적어두세요」류 명령형 문구 금지)
8. **언제 갈 건가요?**: 날짜 선택칸, 비어 있으면 「날짜 고르기」(회색), 고르면 Mono 날짜 + ✕로 지우기
9. 토글 카드 「근처를 지나면 알려주기」 (벽돌 연한 배경 `#f9f0e9`, 테두리 `#e2c9bb`). 설명 줄 없이 제목만
10. 하단 버튼: 가게 이름이 비면 회색 「가게 이름을 적어주세요」, 있으면 검정 「담기」

### B-2. 링크로 가게 찾기

- 헤더 「어느 가게인가요」 · 취소
- 링크 카드: 검정 ▶ 아이콘 + Mono 출처(예: `YOUTUBE 쇼츠`) + 영상 제목 한 줄
  - 제목은 oEmbed로 가져온다 (YouTube: `https://www.youtube.com/oembed?url=…&format=json`). 인스타는 제목을 못 가져오면 `INSTAGRAM 릴스`만 표시
- 「가게」 검색칸(벽돌 테두리, 돋보기 아이콘)에 제목에서 뽑은 검색어를 미리 채움 → 카카오 로컬 검색 결과 3개 목록
- 하나 고르면 폼으로 돌아와 가게·위치·종류가 채워지고 출처 줄이 붙는다

### B-3. 저장 후

- 위시리스트 세그먼트의 묶음 제목: **「예정 · N」**(날짜 있음) / **「언젠가 · N」**(날짜 없음). 기존 「날짜를 정한 곳」 문구는 「예정」으로 교체
- 위시 상세 시트에서 출처가 있으면 「쇼츠에서 보기 ↗」 버튼으로 원본을 연다(외부 앱으로 나가는 화살표 아이콘)
- 「여기 왔어요」 버튼 앞에는 카메라 아이콘만 둔다

1. 커뮤니티 상단 「‹ 내 기록」의 `‹` 글자를 **13px 화살표 SVG**(stroke 2.2, `M15 5l-7 7 7 7`)로 바꾸고 글자와 gap 3px. 크기가 글자와 비슷하게 보이도록.

## E. 도장 · 개수 라벨 (신규)

### E-1. 데이터

`src/lib/labels.ts` 재정리.

- **도장**: 인증된 기록(`verified = true`) 1건 = 도장 1개. 인증 없는 기록은 세지 않음.
  - 10칸 = 도장판 1장. 10칸이 차면 다음 장으로, 판 하나 채울 때마다 뽑기권 +1 (기존 뽑기권 로직에 연결)
- **그릇 수 라벨**(인증 기록 수 기준 8단계):
  `1 첫 기록 · 5 다섯 그릇 · 10 열 그릇 · 30 서른 그릇 · 50 쉰 그릇 · 100 백 그릇 · 200 이백 그릇 · 300 삼백 그릇`
  기존 「첫 한 끼」「인증 기록자」「백 그릇」은 이 단계로 흡수
- **이야기 라벨**은 5개만 남김: 레드 라벨(한 가게 5번) · 다시 그 집(재방문 표시 가게 3곳) · 열 동네(서로 다른 동네 10곳) · 고루 먹는 입(종류 6가지) · 연말의 식탁(12월 인증 3건)
  - 삭제: 한밤의 기록, 아침의 사람, 사진첩, 긴 이야기, 만원의 행복
- 동네 칭호(동·은·금)는 그대로

도장 모양: 기존 인증마크와 같은 24각 톱니 seal(`#b4552d`) 안에 Mono 흰 숫자. 칸마다 -6°/0°/6° 번갈아 살짝 회전.

2. 라벨을 새로 받았으면 카드 아래 띠: 숫자 원 + 「열 그릇 라벨을 받았어요」 / 「뽑기권 1장도 함께 드려요」 + 「리캡 보기 ›」 → E-5

### E-3. 도장 팝업

인증 완료 화면에 들어오자마자 위에 뜬다 (배경 `rgba(28,26,23,.5)`).

- 카드(radius 28, `#fbfaf6`): Mono 「도장판 1 · 10 / 10」 → Gowun 22 「10번째 도장」 → 5×2 도장 칸 → 「한 장을 채웠어요 · 뽑기권 1장」(판을 채웠을 때만) → 검정 「확인」
- 방금 찍은 칸만 찍히는 애니메이션: scale 2.2·-18° → 0.92 → 1·-8°, 0.55s, 0.25s 지연 (Reanimated)
- 빈 칸은 점선 원 `#d6c4b8`

### E-4. 내계정 · 라벨첩

**내계정** (개인 기록장)
- 「도장판」 카드: 「N장째 · x / 10」, 5×2 칸(빈 칸에 다음 번호 Mono), 아래 「채운 판 n장 · 뽑기권 n」
- 「서른 그릇까지 20」 카드: 진행 막대(벽돌)와 양끝 Mono 숫자
- 「모은 라벨」 칩 목록, 방금 받은 라벨은 벽돌 테두리 + 「· 새로」

**라벨첩** (내계정 → 라벨첩 ›)
- 「그릇 수 · 3 / 8」: 4×2 정사각 타일. 받은 것 연한 벽돌, 방금 받은 것 벽돌 채움, 못 받은 것 점선
- 「이야기 · n / 5」: 목록 행 (점 + 이름 + 조건 + 오른쪽 진행도 또는 「받음」)
- 「동네 칭호」 칩

### E-5. 라벨 리캡 (신규 화면 `app/label-recap.tsx`)

라벨을 받을 때마다 볼 수 있는 4장짜리 카드. 검정 배경 `#1c1a17`, 상단 4칸 진행 바, 화면을 누르면 다음 장. 라벨첩에서 받은 라벨을 눌러도 열린다.

1. 표지: 도장 찍히는 애니메이션(150px) + 라벨 이름(Gowun 34) + 받은 날짜
2. 「열 번의 인증이 여기까지 왔어요」: 그 라벨에 들어간 기록을 번호·가게·날짜 목록으로. 처음·마지막은 벽돌 원 + 흰 글씨
3. 숫자 3개: 걸린 날(벽돌 큰 숫자) · 다녀온 곳 수 · 가장 많이 먹은 종류
4. 다음 라벨까지 남은 수 + 진행 막대 + 「공유하기」 / 「닫기」

리캡에 쓰는 숫자는 내 기록 안의 값만. 남과 비교하지 않는다.

### E-6. 리캡 공유 카드

리캡 4장째의 「공유하기」 → 공유 화면.

- 배경: 리캡 마지막 장이 흐리게(blur 2, opacity .38) + 어두운 막(`rgba(10,9,8,.35)`) 뒤에 비친다
- 카드(290 폭, 최소 480 높이, radius 22, 종이색):
  - 맨 위 「DINARY」(Gowun 13), 오른쪽 날짜 없음
  - 도장 64px + 라벨 이름 Gowun 30
  - **발견 한 줄** (Gowun 15, 강조어만 벽돌): 예 「좋았던 메뉴 일곱 개 중 다섯이 **국물**이었어요」
    - 요일·시간대 기반 문장은 쓰지 않는다
    - 「따봉/역따봉」이라는 말은 쓰지 않고 「좋았던/아쉬웠던」으로
    - 후보 규칙 예: 좋았던 메뉴의 공통 종류 / 5점 준 곳 재방문 여부 / 같은 메뉴를 여러 곳에서 / 위시에서 실제로 다녀온 수 — 그중 비율이 가장 높은 하나
  - 가운데: 「내 사진 넣기」 꺼짐 → 도장 10개(5×2) / 켜짐 → 인증 사진 10장(5×2, 3:4 둥근 사각 radius 8, 카드 좌우 여백까지 써서 넓게) + 각 사진 아래 가게 이름 8px 말줄임
  - 하단 3줄: 걸린 시간 / 다녀온 곳 / 가장 많이 먹은 것
- 하단 시트: 「내 사진 넣기」 토글(**기본 꺼짐**, 설명 문구 없음) + 검정 「공유하기」 버튼 하나
- 「공유하기」 → 공유 시트: 인스타 스토리 · 카카오톡 · 메시지 · 이미지 저장 · 링크 복사 · 더보기 (4열 그리드, 원형 아이콘 54px). 실제 앱에서는 공식 아이콘 사용
  - 카드는 `react-native-view-shot`으로 이미지화 → `expo-sharing` / 인스타는 `instagram-stories://share` 스킴, 카톡은 카카오 공유 SDK, 이미지 저장은 `expo-media-library`

## G. 배포 설정 (TestFlight 대화에서 정한 것)

코드 기능 변경은 아니지만 같은 브랜치에 반영.

1. `app.json` → `expo-share-intent` 플러그인 옵션을 `{ "androidIntentFilters": ["text/*"], "disableIOS": true }`로. (iOS 공유 확장은 두 번째 빌드에서 다시 켬. 안드로이드 공유는 유지)
2. `eas.json` → `cli.appVersionSource: "remote"`, `build.production`에 `environment: "production"`, `autoIncrement: true`, `submit.production.ios.ascAppId`(App Store Connect 앱 Apple ID 숫자) 추가. development/preview 프로필에도 `environment` 지정
3. `NAVER_MAP_CLIENT_ID`, Supabase·카카오 키는 EAS 환경변수(production, Sensitive)에서 읽음. `.env` 의존 제거 확인
4. (선택) `npx expo install expo-updates` + `eas update:configure` — JS만 바뀔 때 `eas update --channel production`

- [ ] 위시 폼: 링크·사진 두 입력, 가게 검색 시 위치 자동 채움, 「예정/언젠가」 묶음
- [ ] 캡처 사진은 본인 외 어디에도 안 보임
- [ ] 서랍: 개인일 때 사귄 날·연결 끊기 숨김, `~ ♥ D+N일` 표기, 안내 문구 없음
- [ ] 필터 시트 「포함 / 제외」, 기록 폼 「위치 / 방문일 / 메뉴명」
- [ ] 인증 시 도장 +1, 미인증은 0, 10칸마다 뽑기권
- [ ] 라벨 획득 시 리캡 진입 가능, 라벨첩에서 재열람
- [ ] 공유 카드 사진 토글 기본 꺼짐, 발견 문장에 요일·「따봉」 없음
- [ ] 우리 도장 반쪽/전체 상태가 실제 한 줄 작성 여부와 일치
