## 4. 추천 탭 — `app/(tabs)/recommend.tsx` (시안 v2 5a–5f)

### 4-0 원칙 (모든 화면 공통)

- 셈에는 **인증된 기록만** (`verified_at is not null`). 인증 없는 기록·보관함(`pending`) 제외
- **다른 사람의 사진은 절대 쓰지 않음.** 다른 사람 기록은 숫자(몇 명, 몇 건, 몇 %, 마지막 인증 시각)로만 보임. 사용자 id·닉네임 노출 없음
- 집계 결과가 3 미만인 가게·코스는 내보내지 않음 (개인 특정 방지)
- 추천·투어 후보에 **유료 입점 없음**. 화면에 문구로도 밝힘
- 별점 평균·리뷰 랭킹은 쓰지 않음. 핵심 지표는 **재방문율**

#### 핵심 지표 정의

| 지표 | 계산 |
|---|---|
| 재방문율 | 그 가게를 인증한 사용자 중 2회 이상 인증한 사용자 비율 |
| 오늘 인증 N건 · 마지막 HH:MM | 오늘 0시 이후 인증 수, 가장 최근 인증 시각 |
| 꾸준히 인증 | 최근 N년 동안 매 분기 인증이 있었음 → 「3년째 꾸준히 인증」 |
| 이어 간 동선 | 같은 사용자가 같은 날 A 인증 후 **2시간 안에** B 인증 |
| 머무는 시간 | 위 동선에서 A·B 인증 간격의 중앙값 |

---

### 4-1 화면 구조

추천 탭은 **한 화면 안에서 두 모드**를 전환합니다. 별도 라우트 아님.

```
mode: "now" (기본) | "browse"
```

### 4-1-1 머리

- 라벨 `RECOMMEND` Mono 10, letterSpacing .22em, `#8a8377` + 오른쪽 현재 위치·시각 (「성수동2가 · 토 15:02」, 위치 아이콘 벽돌색)
- 제목 줄: 「지금 뭐 먹지」 와 「둘러보기」 두 글자가 나란히
  - 선택된 쪽: Gowun Batang 28/700 `#1c1a17`
  - 선택 안 된 쪽: 16/700 `#a8a196`, 누르면 그 모드로 전환
  - 전환 애니메이션: font-size·color 0.3s ease (제자리에서 커지고 진해짐 / 작아지고 연해짐)
- 아래 내용은 모드에 따라 통째로 바뀜

> 두 이름은 아직 확정 아님(「지금 뭐 먹지 / 다음엔 뭐 먹지」 등 검토 중). 문자열은 상수 한 곳에 두세요.

## 5. 「지금 뭐 먹지」 모드 (시안 5a)

지금 위치에서 **바로 갈 곳 5곳**을 한 장씩 보여줌.

### 5-1 필터 줄

- 「필터」 버튼 (배경 `#1c1a17`, 글자 `#fbfaf6`, 걸린 조건 수 `#e08a63` Mono)
- 옆으로 지금 걸린 조건 칩. 칩의 ✕ 누르면 그 조건 해제
  - 먹고 싶은 것: 테두리 `#1c1a17`, 배경 `#fbfaf6`
  - 빼고 싶은 것: 「중식 빼기」 배경 `#f2e0d5`, 글자 `#a34d27`
  - 거리: 「도보 10분」
- 높이 36, radius 18, 가로 스크롤

### 5-2 필터 시트 (아래에서 올라옴, 뒤 배경 `rgba(28,26,23,.38)`)

- 제목 「필터」 20/700 + 오른쪽 「초기화」
- **먹고 싶은 것** — 「고르면 이 종류만 찾아요」
- **빼고 싶은 것** — 「최근 3일 먹은 종류는 미리 들어가요」
- 종류 9개(두 섹션 공통): 한식 · 중식 · 일식 · 양식 · 고기 · 국밥·탕 · 면 · 분식 · 아시안
  - 한 종류는 둘 중 한쪽에만. 한쪽에서 고르면 다른 쪽에서 빠짐
- **거리** 세그먼트: 도보 5분 / 10분(기본) / 15분
- 하단 「이 조건으로 다시 고르기」 벽돌색 52px → 시트 닫고 5곳 다시 계산
- 기본값: 빼고 싶은 것 = 최근 3일 인증 기록의 종류(어제 먹은 종류 + 3일 안 2번 이상). 카페·디저트는 자동 제외 안 함
- 사용자가 바꾼 값은 그 날만 기억 (`store.recFilter: {date, inc, exc, dist}`)

### 5-3 카드

카드 전체: radius 24, border 1.5 `#b4552d`, 배경 `#fbfaf6`, 남은 높이를 채움.

**위: 지도 (높이 270)**
- 가운데 내 위치 (점 14px `#4f6b7a` + 흰 테두리 + 연한 원 28px)
- 거리 범위 원(필터 거리 기준, 점선 `#c9a593`) + 「도보 10분」 라벨
- 5곳 번호 마커
  - 기본: 22px 원, 배경 `#fbfaf6`, 테두리 1.5 `#b4552d`, 번호 Mono 10/700 벽돌색
  - **선택(지금 카드의 가게)**: 30px, 배경 `#b4552d`, 흰 테두리 2, 그림자 `0 4px 12px rgba(180,85,45,.45)`, 위에 가게명 말풍선(배경 `#1c1a17`, 11/500 흰 글자), zIndex 위로. 전환 0.25s
  - 마커를 누르면 그 가게 카드로 이동
- 오른쪽 아래 「● 내 위치」 범례
- 지도 SDK는 지금 지도 탭과 같은 것 사용. 상호작용(드래그·줌)은 꺼도 됨

**아래: 가게 설명 (가로 슬라이드)**
- 좌우 스와이프로 5곳 넘김 (50px 이상 끌면 넘어감). 넘길 때마다 위 지도 마커 강조가 따라 바뀜
- 한 장 구성:
  - 번호 원(20px 벽돌색) + 가게명 Gowun Batang 22/700 + 오른쪽 「여기로 갈게요」 버튼
  - 보조줄 12 `#6b665e`: 「한식 · 도보 4분 · 21:00까지」
  - 고른 까닭 3줄 (번호 Mono 11 벽돌색 + 12.5 본문). 예:
    1. 인증한 사람의 42%가 다시 갔어요
    2. 오늘 인증 4건 · 마지막 13:02
    3. 어제 중식을 드셔서 한식으로 골랐어요
- 맨 아래 점 인디케이터 5개 (선택 18×6 벽돌색, 나머지 6×6 `#d8d3c8`)
- 가게 대표사진 없음 (지도가 그 자리를 대신함)

### 5-4 「여기로 갈게요」

- 누르면 길 안내 (외부 지도 앱 딥링크)
- 그 가게를 `store.recHeading = {placeKey, at}` 로 저장 → 2시간 안에 촬영하면 **촬영 후 식당 후보 맨 위**에 올림 (기존 50m 상한 `PICK_MAX_M` 은 그대로)

### 5-5 5곳 고르는 규칙

1. 필터 거리 안 + **지금 영업 중** (브레이크타임 제외)
2. 먹고 싶은 것 있으면 그 종류만, 빼고 싶은 것 제외
3. 점수 = 재방문율 + 오늘 인증 수 가중 + 위시리스트 보너스 + 내가 아직 안 간 곳 보너스
4. 상위 5곳. 까닭 문장은 점수에 가장 크게 기여한 항목 순으로 3개

## 8. 투어 상세 — 신규 `app/recommend/tour/[id].tsx` (시안 5d)

- 도장 카드: 도장 3칸 46px (찍힘 = 벽돌색 원 + ✓, 남음 = 점선 원 + 번호) / 오른쪽 「완주 1,284명 · 진행 중 2,140명」

- 시즌 투어: `ends_at` 지나면 닫힘, 완주자에게 기간 한정 마크

## 9. 화제 투어 (시안 5f) — 투어 상세와 같은 라우트, `kind: "trend"`

방송·유행 메뉴 등 외부 화제로 묶은 투어. 규칙은 일반 투어와 같음(10곳 중 3곳).

- 라벨 `TOUR · 화제 · 2026.09 방영` (`#6b5a8e`)
- 제목 예: 「요리 경연 셰프 투어」 — **실제 프로그램명·로고는 쓰지 않음** (출시 전 권리 확인 필요)
- 도장 카드: 38px 도장 3칸 + 「완주 3,402명 · 진행 중 9,810명」
- **방송 뒤에도 다시 갈까** 카드
  - 후보 10곳 합산 주간 인증 막대그래프 12주 (방송 전 `#d8d3c8`, 방송 후 `#b4552d`), 방송 시점 점선 + 「방송」
  - 숫자 두 개: 「방송 직후 인증 ×7.7」 / 「지금 재방문율 41%」(벽돌색)
- 후보 10곳 목록: 방송 **전에** 내가 인증한 곳은 「방송 전 방문」 검정 태그 + 도장 날짜
- 아래 안내: 「방송 출연 정보는 외부 자료예요. 틀린 곳은 알려 주세요. 후보 선정에 유료 입점은 받지 않습니다.」 — 「알려 주세요」는 신고 폼으로
- 유행 메뉴 투어(예: 모찌)도 같은 틀, 메뉴 단위로 묶음. 기간 끝나면 「2026 겨울 모찌」 같은 한정 마크

## 11. 데이터 · 서버 (제안)

기록이 비공개라 집계는 서버 함수(`security definer`)로. 사용자 id 반환 금지, 3 미만 결과 제외.

```sql
-- supabase/migrations/20261017000000_recommend_v2.sql (제안)
-- 가게별 집계 (매시간 갱신 materialized view 권장)
create materialized view place_stats as
select place_key,
  count(distinct user_id)                                   as users,
  count(distinct user_id) filter (where cnt >= 2)::numeric
    / nullif(count(distinct user_id),0)                     as revisit_rate,
  ...
from (select place_key, user_id, count(*) cnt from restaurants
      where verified_at is not null group by 1,2) t
group by 1 having count(distinct user_id) >= 3;

create function rec_now(p_lat float, p_lng float, p_walk_min int,
  p_inc text[], p_exc text[]) returns table (...);          -- §5-5
create function rec_courses(p_lat float, p_lng float) returns table (...);  -- §4
create function rec_next_after(p_place_key text) returns table (...);      -- §7

create table tours (
  id uuid primary key, kind text check (kind in ('menu','season','trend')),
  title text, region text, need int default 3,
  source_note text, aired_at date, ends_at date
);
create table tour_places (tour_id uuid references tours, place_key text, primary key (tour_id, place_key));
-- 진행도는 내 인증 기록과 tour_places 조인으로 계산 (별도 테이블 없음)
```

- 오늘 인증 수·마지막 인증 시각은 실시간이 필요하면 별도 함수, 아니면 5분 캐시
- 영업 시간은 가게 정보 출처(기존 검색 API) 사용, 없으면 「영업 정보 없음」으로 표시하고 「지금 뭐 먹지」 후보에서 제외
