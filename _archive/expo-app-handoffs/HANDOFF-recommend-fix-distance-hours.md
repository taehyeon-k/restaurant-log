# HANDOFF — 추천 탭 수정: 도보 시간 · 영업시간 제거

대상: `HANDOFF-recommend-all.md` 로 이미 반영된 `expo-app/` 추천 탭
이유: 카카오 로컬 API에는 영업시간·브레이크타임이 없고, 도보 시간은 실제 길과 달라 틀릴 수 있음. **화면의 모든 숫자는 좌표 계산 또는 인증 기록에서만 나오게** 바꿉니다.

---

## 0. 바꾸는 규칙 한 줄 요약

| 지금 | 바뀐 뒤 |
|---|---|
| 도보 N분 | 직선거리 `380m` / `1.2km` |
| 21:00까지 · 영업 중 · 브레이크타임 피함 | 삭제 → 인증 기록 문구로 대체 |
| 지금 영업 중인 곳만 후보 | 최근 같은 요일·시간대에 인증 있는 곳만 후보 |
| 코스 시각·총 소요시간 | 삭제 → 순서와 사람 수만 |

## 1. 거리 표시 — 공통 함수

신규 `src/lib/distance.ts`

```ts
// 직선거리(m), haversine
export function distanceM(a: {lat:number;lng:number}, b: {lat:number;lng:number}): number

// 1000m 미만 "380m"(10m 단위 반올림), 이상 "1.2km"(소수 1자리)
export function formatDistance(m: number): string
```

- 앱 전체에서 「도보 N분」 문자열 생성하는 곳을 모두 `formatDistance` 로 교체
- 분속 환산(67m/min 등) 코드가 있으면 삭제

## 2. 「지금 뭐 먹지」 (§5)

### 2-1 필터 (§5-1, §5-2)
- 거리 세그먼트: `도보 5분 / 10분 / 15분` → **`500m / 1km / 2km`**, 기본 `1km`
- 칩 문구: `도보 10분` → `1km 안`
- `store.recFilter.dist` 값을 분 → 미터(500 | 1000 | 2000)로. 저장된 옛 값(5|10|15)은 읽을 때 1000으로 초기화

### 2-2 지도 (§5-3)
- 범위 원 라벨 `도보 10분` → `1km`
- 원 반지름은 필터 거리(m) 그대로

### 2-3 카드 보조줄
- `한식 · 도보 4분 · 21:00까지` → **`한식 · 380m`**

### 2-4 고른 까닭
- 영업시간 관련 문장 삭제
- 쓸 수 있는 문장(점수 기여 순으로 3개):
  - 인증한 사람의 42%가 다시 갔어요
  - 오늘 인증 4건 · 마지막 13:02
  - 지난 4주 토요일 이 시간대에 인증 9건
  - 어제 중식을 드셔서 한식으로 골랐어요
  - 위시리스트에 담은 지 32일 된 곳이에요

### 2-5 후보 고르는 규칙 (§5-5) — 1번 교체
- ~~필터 거리 안 + 지금 영업 중 (브레이크타임 제외)~~
- **필터 거리 안 + 최근 4주 같은 요일, 지금 시각 ±1시간 안에 인증 1건 이상**
- 후보가 5곳 미만이면: 요일 조건을 빼고(최근 4주 같은 시간대) 다시 → 그래도 부족하면 있는 만큼만

### 2-6 카카오맵 링크
- 카드에 작은 텍스트 버튼 「카카오맵에서 보기」 추가 (가게명 줄 아래, 12 `#8a8377`, 밑줄 없음, 터치 44)
- 카카오 로컬 API 응답의 `place_url` 을 그대로 엶 (`Linking.openURL`)
- 영업시간이 궁금한 사람은 여기서 확인

## 3. 「둘러보기」 (§6)

### 3-1 지금 시작하는 코스 카드 (§6-1)
- 두 칸의 `15:10 · 카페` / `17:30 · 양식` → **`카페` / `양식`** (시각 삭제)
- 가운데 `도보 6분` → **`450m`**
- 아래 줄 `이 순서로 인증한 사람 87명 · 총 2시간 30분` → **`이 순서로 인증한 사람 87명`**

### 3-2 다시 가는 사람이 많은 곳 (§6-3)
- 이미 `한식 · 380m` 형식이면 그대로. 「도보」 표기 있으면 교체

## 4. 코스 상세 (§7)

- 머리 `총 2시간 30분 · 도보 6분 · 2곳` → **`450m · 2곳`**
- 지도 경로 라벨 `도보 6분 · 450m` → **`450m`**
- 가게 줄
  - `영업 중 · 19:00까지` / `17:30 저녁 시작` → 삭제, 대신 **`오늘 인증 6건 · 마지막 16:48`**
  - 오른쪽 Mono `15:10 · 머묾 40분` / `17:30 · 오늘 인증 6` → **`재방문 36%`** 하나만
- 고른 까닭 2번 `지금 출발하면 두 곳 모두 영업 시간 안에 들어가요.` → **`지난 4주 이 시간대에 두 곳 모두 인증이 있어요.`**
- 각 가게 줄에 「카카오맵에서 보기」 (§2-6 과 같음)

### 코스 데이터
- 「머무는 시간」 계산·표시 삭제 (두 인증 간격 중앙값 관련 코드 제거 가능)
- 「지금 시작하는 코스」 조건: ~~모든 가게가 예상 도착 시각에 영업 중~~ → **코스의 모든 가게에 최근 4주 같은 시간대 인증 있음**
- 출발 범위: ~~도보 15분~~ → **2km**

## 7. 데이터 · 서버 (§11)

- `rec_now(p_lat, p_lng, p_walk_min, ...)` → **`p_radius_m int`** 로 인자 교체
- `rec_courses` 출발 반경도 `p_radius_m` (기본 2000)
- 영업시간 관련 컬럼·외부 API 호출(구글 Places 등)을 추가했다면 **제거**
- 시간대 인증 수 집계 추가 (후보 필터·까닭 문장용):

```sql
-- 가게 × 요일 × 시간 인증 수 (최근 4주), materialized view 권장
create materialized view place_hourly as
select place_key,
       extract(dow  from verified_at at time zone 'Asia/Seoul')::int as dow,
       extract(hour from verified_at at time zone 'Asia/Seoul')::int as hour,
       count(*) as n
from restaurants
where verified_at is not null
  and verified_at > now() - interval '28 days'
group by 1,2,3;
```

- 3 미만 결과 제외 원칙은 가게 단위 그대로 (시간대 수 자체는 숫자로만 쓰므로 노출 가능)
